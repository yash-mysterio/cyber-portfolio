TaskParty: The Frontend Foundation

TaskParty is a gamified task management web app where users collaborate in parties and earn XP as they get things done. My part was the groundwork that let a team of five build it at the same time: the frontend structure, the routing, the shared data and the Git workflow.

00 / Scope

University group project. This page covers only my contributions and doesn't describe my teammates' work, so it doesn't name them. The features other team members built on top of this foundation aren't described here.

01 / The project

A task manager with a party system

TaskParty is a collaborative task management web application. Users organise tasks together in parties and track progress through an XP reward system, which turns shared to-do lists into something closer to a game.

02 / My role

Five people, one frontend

When five people build a single shared frontend, the first problem isn't any one feature. It's making sure everyone can build their own part at the same time without getting in each other's way. My contribution was the foundation that made that possible: the project structure, the routing, the shared data, and the workflow for combining everyone's work.

03 / What I built

Six pieces of groundwork

  • Frontend architecture. Set up the React and Vite foundation and organised the project structure to support modular development across the five team members.
  • Client-side routing. Implemented React Router navigation for the Login, Dashboard and Party View pages, including dynamic routing for individual parties (/party/:partyId).
  • Mock data. Designed structured JSON mock data representing users, parties, tasks and the relationships between them, to support frontend development and testing.
  • Integration points. Configured the application entry points and routing structure so teammates could develop and integrate their assigned features within one shared frontend.
  • Version control workflow. Established a Git branching workflow using main, develop and feature branches, with pull request reviews.
  • Validation. Checked the initial implementation through development server testing, ESLint checks and successful production builds.
04 / Scope of the work

Foundation, not features

This was groundwork rather than the feature set. The data I designed was mock JSON, not a database or a backend, so my contribution doesn't cover persistence or server-side integration. What it does cover is the part that everything else depends on: a structure, a set of routes and a workflow that other people could build on without waiting for each other.

05 / Outcome

What it delivered

The foundational frontend architecture and development workflow for a five-member collaborative project, supporting parallel development and the integration of application features.
